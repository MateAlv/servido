# 0001 — Stack and repository layout

- **Status**: Accepted
- **Date**: 2026-10-18

## Context

Six students build an MVP in six one-week sprints with most code generated by AI agents. It will never serve more than one user at a time and must be cheap to run on a single AWS free-tier account. The team chose React + TypeScript for the frontend and Python for the backend.

## Decision

- One repository with `backend/` and `frontend/`.
- **Backend**: Python 3.12, FastAPI, SQLAlchemy 2, Alembic, PostgreSQL 17, managed with uv. One API process; no queues, caches or microservices.
- **Frontend**: React + TypeScript, built with Vite, React Router, TanStack Query, and a typed client generated from the backend's OpenAPI document.
- **Local development**: `docker compose` runs Postgres, the API and the web app.

## Consequences

- FastAPI's OpenAPI document is the API contract. It is committed (`frontend/src/api/openapi.json`) so contract changes show up in PR diffs, and CI fails if it is stale.
- AI agents know this stack very well, which lowers the risk of generated code drifting from conventions.
- FastAPI returns 422 for invalid input by default; the specs require 400, so a global handler converts it.
